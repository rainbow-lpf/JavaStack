# 常见加密算法 — 面试总结

> 目录：`com.axon.java.stack.加密算法`

---

## 一、三大类加密算法速记

| 类型 | 算法 | 特点 | 一句话 |
|------|------|------|------|
| **对称加密** | AES、DES | 加解密用同一把钥匙，快 | "同一把钥匙，快快开门" |
| **非对称加密** | RSA、DSA | 公钥加密，私钥解密，安全但慢 | "一把锁给所有人，钥匙只在自己手里" |
| **哈希加密** | MD5、SHA | 不可逆，固定长度摘要 | "把西瓜变成指纹，指纹无法变回西瓜" |

---

## 二、对称加密（AES、DES）

### 2.1 原理

```
同一个密钥，加密和解密都用它。

原文 "hello"
   ↓ 密钥 key123 加密
密文 "aB3$kL9@"
   ↓ 密钥 key123 解密
原文 "hello"
```

### 2.2 特点

| 优点 | 缺点 |
|------|------|
| 速度极快 | 密钥泄露 = 数据全暴露 |
| 适合大量数据（文件、数据库字段） | 密钥配送困难——传输密钥本身就是安全问题 |

### 2.3 使用场景

```
数据库敏感字段加密（手机号、身份证）
文件加密（压缩包密码）
HTTPS 里的数据传输加密（对称+非对称混用）
```

### 2.4 AES vs DES

| | AES | DES |
|------|------|------|
| 安全性 | ✅ 高（128/256 位） | ❌ 低（56 位，暴力可破） |
| 速度 | 快 | 慢 |
| 现状 | 主流推荐 | 已淘汰 |

## 三、非对称加密（RSA、DSA）

### 3.1 原理

```
公钥 和 私钥 是一对。
公钥加密 → 私钥解密（加密通信）
私钥加密 → 公钥解密（数字签名）

         持有者1                         持有者2
     ┌─────────────┐               ┌─────────────┐
     │ 公钥：公开   │               │ 公钥：公开   │
     │ 私钥：自己留 │               │ 私钥：自己留 │
     └─────────────┘               └─────────────┘

加密通信：
  持有者2 用持有者1的公钥加密 → 只有持有者1的私钥能解密

数字签名：
  持有者1 用自己私钥加密"摘要" → 持有者2 用持有者1的公钥解密验证
  → 能解开就是持有者1发的，没被篡改
```

### 3.2 特点

| 优点 | 缺点 |
|------|------|
| 不需要传输密钥，公钥公开 | 加密解密慢（是对称的几百倍） |
| 天然支持身份认证 | 密钥长 |

### 3.3 使用场景

```
HTTPS 握手阶段（用 RSA 传输对称密钥）
数字签名（合同、证书验证）
SSH 密钥登录
```

### 3.4 RSA 核心公式

```
① 选两个大质数 p、q
② n = p × q （n 公开）
③ 公钥 e：和 (p-1)(q-1) 互质
④ 私钥 d：e × d ≡ 1 (mod (p-1)(q-1))

加密：密文 = 明文^e mod n
解密：明文 = 密文^d mod n
```

## 四、哈希加密（MD5、SHA）

### 4.1 原理

```
"hello world"  →  MD5 eb63bbbe01eeed093cb22bb8f5acdc3"
                                                    ↑
                                          固定 32 位，不可逆
```

### 4.2 特点

| 特点 | 说明 |
|------|------|
| **不可逆** | 不可能从哈希值反推出原文 |
| **定长输出** | 不管输入多大，输出固定长度 |
| **雪崩效应** | 原文改一个字符，哈希值天翻地覆 |
| **碰撞** | 理论上不同输入可能产生相同哈希（MD5 已被证明不安全） |

### 4.3 MD5 vs SHA

| | MD5 | SHA-256 |
|------|------|------|
| 输出长度 | 128 位 | 256 位 |
| 安全性 | ❌ 已被攻破，有碰撞 | ✅ 安全 |
| 速度 | 快 | 较慢 |
| 推荐 | 不推荐用于安全场景 | 推荐 |

### 4.4 使用场景

```
密码存储：存哈希，不存明文
文件完整性校验（下载文件后对比哈希值）
Git 的 commit id
区块链（SHA-256）
```

### 4.5 密码加盐

```
❌ 只存 MD5("123456") = "e10adc3949ba59abbe56e057f20f883e"
   → 彩虹表直接反查 → 密码泄露

✅ 存 MD5("123456" + salt) = "xxx"
   → 每个用户 salt 不同 → 同一个密码不同哈希 → 彩虹表无效
```

## 五、面试常考三点

### 5.1 HTTPS 用到了哪些加密算法？

```
① 非对称（RSA）：证书验证 + 传输对称密钥
② 对称（AES）：传输正文数据（快）
③ 哈希：验证证书签名 + HMAC 校验数据完整性

非对称传钥匙 → 对称传数据 → 哈希验身份
```

### 5.2 对称和非对称有什么区别？

| | 对称 | 非对称 |
|------|------|------|
| 密钥 | 1 把（加密解密同） | 2 把（公钥 + 私钥） |
| 速度 | 快 | 慢 |
| 安全 | 密钥泄露就完蛋 | 公钥公开也不怕 |
| 场景 | 大量数据加密 | 密钥传输、数字签名 |

### 5.3 密码存数据库用什么加密？

> **哈希（SHA-256 + 随机盐）。** 不能对称（可解密是致命的），不能非对称（太慢），不能 MD5（已被破解）。加盐防彩虹表。

## 六、面试话术（30 秒版）

> **三大类型：** ① 对称加密（AES）同一把钥匙，快，适合大量数据；② 非对称加密（RSA）公钥加密私钥解密，安全但慢，用于 HTTPS 握手和数字签名；③ 哈希加密（SHA-256）不可逆，定长输出，用于密码存储和完整性校验。
>
> **密码存数据库：** SHA-256 + 随机盐，防彩虹表。MD5 已不安全。
>
> **HTTPS：** RSA 传钥匙 → AES 传数据 → 哈希做签名检验。
