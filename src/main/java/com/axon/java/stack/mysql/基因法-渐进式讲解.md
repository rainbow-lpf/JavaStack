# 基因法：从零到精通

> 分库分表中"两个字段都能精确路由"的最经典方案。从十进制直觉入手，彻底讲透"嵌入"到底嵌的是什么。

---

## 一、先建立直觉：分表就是看"尾巴"

分 100 张表，表号 = `字段 % 100` = **字段的最后两位数字**。

```
userId = 8849527  → 最后两位 27 → 数据放第 27 张表
```

记住这个直觉：**% 100 只看最后两位。% 8 只看二进制最低 3 位。**

---

## 二、矛盾：orderId 的尾巴和 userId 对不上

```
userId 最后两位 = 27 → 第 27 张表

雪花算法生成 orderId = 2026083017290343
  orderId 最后两位 = 43 → 第 43 张表

❌ 两张表对不上：
   按 userId 查 → 27 号表
   按 orderId 查 → 43 号表
   同一条订单，两个字段指向不同表 → 数据没法同时满足两个查询
```

**分表的核心约束：一条数据只能存在一张物理表里。** 如果 userId 和 orderId 算出不同表号，这条订单到底放哪张？放 27 号表，按 orderId 查就找不到；放 43 号表，按 userId 查就找不到。

---

## 三、基因法的解法：硬改 orderId 的尾巴

> **生成 orderId 时，把它最后两位数字硬改成 userId 的最后两位。**

```
userId 最后两位 = 27
orderId 原始最后两位 = 43

改成：orderId = 2026083017290327   ← 最后两位从 43 改成 27
```

改完之后：

```
userId  % 100 = 27  → 第 27 张表
orderId % 100 = 27  → 第 27 张表   ✅ 同一张表！
```

**就这么简单。orderId 自带 userId 的"尾巴"，两个数 % 100 结果必然相同。**

---

## 四、为什么"改尾巴"就能保证取模同片

核心数学事实：

```
一个数 % 100，只看它最后两位十进制数字。
一个数 % 8，只看它二进制最低 3 位。

所以只要：
  orderId 的尾巴 == userId 的尾巴
就必然：
  orderId % N == userId % N
```

**"嵌入"的全部含义 = 不是把 userId 整个塞进去，只塞它最低几位（够算取模就行）。**

---

## 五、二进制版本（真实场景：8 张表）

实际分 8 张表，8 = 2³，所以表号 = `字段 % 8` = **字段二进制的最低 3 位**。

```
userId = 9527
  9527 二进制 = ...111 → 低 3 位 = 111 = 7
  → userId % 8 = 7 → 第 7 张表
```

生成 orderId 时，把 orderId 二进制的最低 3 位硬改成 `111`：

```
orderId 原来低 3 位 = 010（=2）
改成 111（=7）
  → orderId % 8 = 7 → 第 7 张表 ✅
```

两个字段 % 8 都等于 7 → 同一张表。

> 注意：上面是"改尾巴"的直观理解。真实实现不是改，而是**发号时主动把序列号左移 k 位、低 k 位固定填基因**，否则同毫秒会重复——见第六节。

---

## 六、代码实现：正确的写法是"让位"，不是"替换"

> ⚠️ **先纠错：不能直接替换低 k 位。** `(raw & ~mask) | gene` 这种写法会导致同一毫秒内 ID 重复，唯一性崩掉。

### 为什么"直接替换"会重复

雪花唯一性靠 `时间戳 + 机器ID + 序列号`，其中序列位 12 位，同一毫秒内靠它自增保证不重。

直接替换低 3 位时：

```
同一毫秒内：
  seq = 0 → 低 3 位 000 → 替换成 111
  seq = 1 → 低 3 位 001 → 替换成 111
  seq = 2 → 低 3 位 010 → 替换成 111

三个 ID 的低 3 位都变成 111，高位序列部分都相同
→ 生成出来的 ID 完全一样 ❌ 重复！
```

### 正确做法：序列号让出低 k 位，基因固定填低位

```java
public class GeneSnowflake {

    // 分 8 张表 → 基因位 = 3 位（2^3 = 8）
    private static final int GENE_BITS = 3;
    private static final long GENE_MASK = (1L << GENE_BITS) - 1; // 0b111

    public long nextOrderId(long userId) {
        long time  = System.currentTimeMillis();   // 41 位时间戳
        long worker = workerId;                     // 10 位机器 ID
        long seq   = sequence();                    // 序列号，每毫秒自增
        long gene  = userId & GENE_MASK;            // 基因：userId 低 3 位

        // 序列号左移 3 位，让出低 3 位给基因；seq 自增保证高位不重复
        long orderId = (time << 22) | (worker << 12) | (seq << GENE_BITS) | gene;
        return orderId;
    }

    // 两个字段路由结果一致
    public int shardByOrderId(long orderId) { return (int) (orderId & GENE_MASK); }
    public int shardByUserId(long userId)   { return (int) (userId   & GENE_MASK); }
}
```

### 代码走一遍

```
userId = 9527
  gene = 9527 & 0b111 = 111（=7）

同一毫秒内 seq 自增：0, 1, 2, 3 ...

  seq=0：orderId = 时间戳 | 机器ID | 000<<3 | 111 → 高位不同，低 3 位 = 111
  seq=1：orderId = 时间戳 | 机器ID | 001<<3 | 111 → 高位不同，低 3 位 = 111
  seq=2：orderId = 时间戳 | 机器ID | 010<<3 | 111 → 高位不同，低 3 位 = 111

低 3 位恒等于基因 111，高位靠 seq 自增区分 → 不重复 ✅

按 orderId 查：orderId & 0b111 = 7 → 第 7 片
按 userId  查：userId   & 0b111 = 7 → 第 7 片  ✅ 同片
```

## 七、位数的代价：基因挤占序列位

雪花 ID 低位布局：

```
[ 时间戳 41 bit ][ 机器位 10 bit ][ 序列位 12 bit ]
                                    ↑ 基因占低 k 位，序列号让位

基因位 k=3：序列剩 9 位 → 单机每毫秒 2^9 = 512 个 ID
基因位 k=8：序列剩 4 位 → 单机每毫秒只剩 16 个 ID
```

> **基因位数 = log2(分片数)，分片越多，吃掉的序列位越多，单机并发上限越低。**
> 优化变体：基因不放序列位，放机器位（路由时 `(orderId >> 12) & mask`），序列保留全宽，但牺牲机器 ID，多机发号需外部协调。

---

## 八、三个硬约束

| 约束 | 说明 |
|------|------|
| 表数必须是 2 的幂 | 256、512、1024。100 张表的话 `%` ≠ 低位截取，基因法失效 |
| 基因字段必须是数字 | 字符串 ID 取不了位 |
| ID 生成时该字段必须已确定 | orderId 生成时 userId 必须已知；"先建单后绑用户"就嵌不进去 |

---

## 九、优缺点总结

| 优点 | 缺点 |
|------|------|
| 一份数据、零冗余、强一致 | 基因位数决定分片数上限 |
| SQL 无感知，不改查询逻辑 | ID 生成器要自己改造 |
| 无二次查询开销 | **只能救一个维度**（第 3 维度起换异构表/ES） |

## 十、一句话类比 + 总结

```
orderId = 身份证号，userId = 出生地
基因法 = 生成身份证号时，把地区码固定填成出生地代码
→ 看身份证号就知道出生地，两个字段指向同一个地方
```

> **本质：把 A 字段的"路由基因"写进 B 字段的冗余位数里，让 B 字段天生带着 A 的路由信息。**

```
分表看尾巴（% N 只看最低几位）
→ 让 orderId 的尾巴 = userId 的尾巴
→ 两键 % N 必然同片
→ 生成时让位：序列号左移 k 位，低 k 位填基因
→ 成本：基因位数挤占序列位，每毫秒容量缩到 2^(12-k)
```

## 常见追问

**Q1：基因法最多几个字段？**
两个。一个主分片键 + 一个基因维度。第 3 个维度再嵌基因会挤爆位数（序列位/机器位归零），换异构索引表。

**Q2：和组合分片键 `hash(userId, orderId)` 有什么区别？**
组合键必须两个字段同时出现才精确路由，少一个就广播；基因法两个字段**各自单独**都能精确路由。

**Q3：为什么不用 user_id 直接拼在 order_id 字符串里？**
那 order_id 会变长、且可被反解出用户隐私。基因法只占几个 bit，orderId 仍是定长数字 ID。

**Q4：直接替换低 k 位会导致 ID 重复吗？**
会。同一毫秒内序列号 0、1、2 的低 k 位各不相同，替换成基因后就全一样了，唯一性崩掉。正确做法是**序列号左移 k 位、低 k 位固定填基因**，序列号自增保证高位不同、不重复。
